## Architecture

This is a **production-grade E2E ML serving platform** built on Apache Airflow. It implements *safe model replacement* — not just model deployment — using promotion/shadow branching, pre-deployment quality gates, and automated rollback.

**Two-repo design:**
- **This repo (`airflow-dags-dev`):** DAG orchestration + deployment policies
- **`mlops-infra-gitops`:** Kubernetes infrastructure (Helm, ArgoCD)
- **Shared state:** S3 (features/artifacts) + MLflow Registry (model versions/aliases)

### Core DAGs (`dags/`)

| DAG | Purpose |
|---|---|
| `e2e_full.py` | Main pipeline: data → train → branch → deploy → observe → rollback |
| `dp_feature_pipeline.py` | Feature extraction, validation, S3 storage |
| `rollback_manual.py` | Emergency manual rollback trigger |
| `feast_materialize.py` | Feature Store materialization via KubernetesPodOperator |

### SSOT Design Pattern

All identifiers, thresholds, and variable keys live in two canonical files:

- **`dags/mlops_lib/core/ids.py`** — Task IDs, XCom keys, shadow reason codes, TaskGroup suffixes (`_S` suffix = suffix-only variant for use inside TaskGroups)
- **`dags/mlops_lib/core/policy.py`** — Timeouts, quality thresholds, Airflow Variable keys, and the `Settings` dataclass

The `Settings.load()` method resolves config at runtime with priority: env var > Airflow Variable > hardcoded default. The `E2E` alias at the top of `e2e_full.py` imports both ID classes for compressed access.

**Never hardcode task IDs, XCom keys, or threshold values.** Always reference `ids.py` and `policy.py`.

### Promotion / Shadow Branch Logic

```
Train → branch_by_accuracy (BranchPythonOperator)
├─ accuracy ≥ threshold AND drift OK → Promotion path
│   register → sensor → deploy → commit_current_json → reload → observe
└─ Otherwise → Shadow path (deploy only, no commit/reload)
    Reasons: drift_detected | below_threshold | train_skipped | accuracy_invalid
```

Drift detection runs pre-branch using `mlops_lib/quality/drift_gate.py` (KS-stat D > 0.20 = force shadow). The branch result and shadow reason are passed downstream via XCom.

### Task Organization

- **`dags/e2e_full.py`** — Defines the dependency graph only; no business logic
- **`dags/pipelines/p_*.py`** — Task callables (train, drift, observe, register, reload, triton)
- **`dags/ml_code/`** — Core ML operations (train_model, register_model, triton_deploy, triton_actions)
- **`dags/mlops_lib/`** — Shared library: quality gates, observability, rollback, HTTP utilities, SSOT

### Rollback Policy

Rollback is **minimal by design**: only restores Triton repository snapshot + `current.json`. It does NOT roll back repository SSOT on FastAPI reload failure (reverting shared state is riskier than a pod-local mismatch). Rollback tasks use `trigger_rule=ONE_FAILED` on `[deploy, commit, observe]`.

### Observability

Post-deploy metrics are scraped from Prometheus over a 60–180s window. Thresholds (error rate, p95 latency) are defined in `policy.py`. Silent observation failures default to "observe success" to avoid false-positive rollbacks.

### External Integrations

- **Triton Inference Server** — ONNX model serving; dynamic batching config generated by `mlops_lib/core/triton_config.py`
- **FastAPI** — Variant routing (promotion/shadow split)
- **MLflow Registry** — Model versioning and alias management
- **Prometheus** — Post-deploy metrics collection
- **S3/MinIO** — Feature store + artifact repository
- **ArgoCD** — GitOps K8s synchronization
